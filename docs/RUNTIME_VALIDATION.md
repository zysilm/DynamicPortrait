# Runtime validation

Current status: Release compilation and standalone mathematical tests can be performed outside the game. No in-game result is claimed by this checklist.

1. Load the Release DLL with its dependencies. Confirm `/dportrait` opens and capture starts disabled, with no native hooks installed until explicitly started. If a signature fails at start, confirm a visible error and normal game rendering.
2. In a quiet area, enable the default self/chest camera. Confirm the main view remains independently controllable and the portrait faces the character. Check captures and suppressed Presents increase together, and that the window is not a main-view screenshot.
3. Rotate the normal camera away from the actor; turn/move/emote the actor. Check facial animation, culling, shadows, first-person visibility, apparent animation speed and input response. Observe both views for flashes and ghosts.
4. Compare graphics settings, especially TAA / DLSS / FSR / dynamic resolution. Record any history contamination or projection mismatch. Do not claim these combinations supported until verified.
5. Choose current target, lock a character, clear/change target, then make that character disappear. Ensure the locked camera never silently attaches to another object reusing an address. Try missing bones, different races, monsters, mounts and model replacement.
6. In Camera, select Head and enable the optional **Lock bone in frame** (off by default). Check that enabling it does not add a 90-degree roll. Run, turn, jump, and emote: rigid head landmarks should stay at the same portrait position and orientation while the body and background move. Facial expressions still animate. Disable the lock and check character/bone/world orientation and smoothing; enable it again and check immediate tracking without smoothing lag. Change angles, distance, near clip, FOV and offsets in both modes. Resize the window and output texture repeatedly. Check portrait proportions and recovery with `/dportrait reset`. Use **Reset all settings** to restore Chest with bone locking off, clear the locked subject, stop rendering, and preserve both windows' positions and sizes. Scroll each tab to its limits and confirm the toolbar and tab bar remain visible. Move and resize both windows before resetting settings, then confirm their geometry is retained. Use Glamourer to change race while rendering, with the lock both off and on: capture should pause during redraw and resume automatically without a rendering fault, stale skeleton names, or retained calibration from the old model.
7. Hide, collapse and close the window. Verify capture stops and normal ticks continue. Stop capture; verify CPU/GPU cost returns toward baseline.
8. Test territory transitions, teleport, GPose, cutscenes, logout and login. No stale pointer reads or stale target portrait should occur. Locked targets must clear on territory changes.
9. Test plugin unload/reload both idle and rendering, including unload initiated during a framework callback. Verify camera restoration, no remaining hook callbacks, no unreleased SRVs and no crash. Hook cleanup is synchronous to match Dalamud's plugin-scoped service lifetime; texture release retains the backend until active callbacks and subsequent frames finish. A queued capture marker retains a real scene texture binding if the hook is removed. Zero-target unbind markers are forbidden: this client's native routine still reads target[0].
10. Compare disabled / game-synchronized legacy capture at 256 / 512 / 1024 output. Finite investigations can still cap capture at 5 / 15 / 30 / 60 FPS for timing comparisons. Record game build, Dalamud version, CPU, GPU, scene resolution, graphics settings and observed frame time. Use external GPU profiling for GPU measurements.

The experimental render-only prototype crashed during a longer test. Version 0.1.0.14 removes scene update replay and uses camera-local preparation. A bounded live run completed 399 captures without a fault, but exported portraits still show the wrong character orientation. The candidate therefore fails image validation and is restricted to explicit finite investigations; ordinary Start requests stay stopped. The legacy backend remains default. Independent temporal histories, independently sized scene targets, moving-camera quality, redraws, and long-session stability also need runtime validation. See [crash analysis and live results](RENDER_ONLY_CRASH_0.1.0.14.md).

Version 0.1.0.15 corrects legacy simulation timing and follows game frames instead of the persisted refresh limit. A live capped run confirmed zero portrait task deltas and no missing elapsed interval in the following main tick. A synchronized run completed 387 portrait ticks without a recorded fault. These runs do not establish that continuous walking is free of visible jitter. See [legacy timing evidence](LEGACY_TIMING.md).

Version 0.1.0.16 fixes a separately confirmed main-camera matrix overwrite. Portrait capture now leaves Scene.Camera untouched. Live restore observations fell from 286/286 overwritten main-view inputs to 0/94. See [camera restoration evidence](CAMERA_RESTORATION.md).

Version 0.1.0.17 prevents the legacy portrait tick from driving the main gameplay camera follow update a second time, addressing the interaction reported with CombatSimulator Active Camera. Input/state sampling remains enabled. Validate continuous walking, orbit/zoom input, camera transitions, and model redraws with Active Camera both enabled and disabled. See [compatibility analysis](ACTIVE_CAMERA_COMPATIBILITY.md).
